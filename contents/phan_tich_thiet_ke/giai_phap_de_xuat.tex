\section{Giải pháp đề xuất}
    Nhằm hiện thực hóa mục tiêu xây dựng một IoT Gateway có tính linh hoạt cao, khả năng cấu hình linh hoạt, đồng thời tối ưu hóa chi phí sản xuất và rút ngắn thời gian triển khai cho các kịch bản ứng dụng đa dạng, giải pháp đề xuất là tích hợp giữa kiến trúc phần cứng mô-đun và hệ thống xử lý phân tán.

    \subsection{Giải pháp phần cứng}
        Giải pháp phần cứng tập trung vào việc xây dựng một hệ sinh thái mô-đun hóa toàn diện, cho phép tối ưu hóa khả năng tích hợp, bảo trì và nâng cấp hệ thống mà không yêu cầu thay đổi thiết kế cốt lõi.

        \begin{itemize}
            \item \textbf{Thiết kế Bo mạch chủ (Baseboard) chuẩn hóa:} 
            Xây dựng Baseboard đóng vai trò là nền tảng trung tâm, tích hợp các khe cắm với giao tiếp vật lý và giao thức được chuẩn hóa, tạo điều kiện kết nối đồng bộ với các loại Module Adapter khác nhau.

            

            \item \textbf{Phát triển hệ thống Module Adapter linh hoạt:} 
            Các Module Adapter được thiết kế để đóng vai trò là cầu nối trung gian, có nhiệm vụ chuyển đổi và chuẩn hóa các chuẩn giao tiếp của các mô-đun thương mại hiện có trên thị trường về giao thức nội bộ thống nhất của Gateway.

            \item \textbf{Tối ưu hóa hiệu năng và chi phí bằng giải pháp Vi điều khiển (MCU):} 
            Thay vì sử dụng các bộ vi xử lý (CPU) hiệu năng cao vốn làm tăng đáng kể giá thành linh kiện và chi phí gia công PCB (do yêu cầu về mạch in nhiều lớp phức tạp), nhóm quyết định sử dụng dòng vi điều khiển (MCU) làm nhân xử lý chính dựa trên các tiêu chí:
            \begin{itemize}
                \item Cân bằng giữa giá thành thấp và hiệu năng xử lý đủ mạnh mẽ, sở hữu tài nguyên phần cứng đủ nhiều và hỗ trợ đa dạng các giao thức ngoại vi.
                \item Hệ sinh thái thư viện mã nguồn mở dồi dào và cộng đồng hỗ trợ lớn, giúp đẩy nhanh tốc độ phát triển và tối ưu hóa mã nguồn (Firmware).
                \item Đặc tính tiêu thụ năng lượng thấp, đáp ứng tiêu chuẩn khắt khe của các thiết bị IoT vận hành liên tục hoặc sử dụng nguồn năng lượng hạn chế.
            \end{itemize}

            \item \textbf{Kiến trúc xử lý Dual-MCU:} 
            Để giải quyết giới hạn về tài nguyên bộ nhớ khi phải tích hợp đồng thời nhiều thư viện giao thức phức tạp, nhóm đề xuất kiến trúc sử dụng hai MCU chuyên biệt hóa nhiệm vụ:
            \begin{itemize}
                \item \textbf{WAN-MCU (Master):} Chịu trách nhiệm quản lý luồng dữ liệu mạng diện rộng (WAN), điều phối toàn bộ hoạt động của hệ thống và quản trị các tác vụ cấp cao.
                \item \textbf{LAN-MCU (Slave):} Tập trung xử lý các giao tiếp mạng nội bộ (LAN), quản lý việc thu thập dữ liệu từ các mô-đun ngoại vi và thiết bị đầu cuối.
            \end{itemize}
            Hai khối xử lý này liên kết chặt chẽ thông qua giao thức truyền thông tốc độ cao và hệ thống tín hiệu điều khiển logic, đảm bảo tính đồng bộ và độ trễ thấp trong quá trình trao đổi thông tin.

            
        \end{itemize}

    \subsection{Giải pháp phần mềm}
        Giải pháp phần mềm được xây dựng nhằm đáp ứng các yêu cầu cốt lõi của hệ thống IoT Gateway bao gồm: tính module hóa (Modularity), khả năng cấu hình linh hoạt (Configurability), độ ổn định – tin cậy cao, khả năng mở rộng và dễ bảo trì. 

        Phần mềm phải tận dụng hiệu quả kiến trúc \textbf{Dual-MCU Master--Slave}, phân tách rõ ràng trách nhiệm giữa hai vi điều khiển để tối ưu tài nguyên phần cứng, đồng thời bảo đảm luồng dữ liệu thông suốt từ thiết bị cảm biến tới nền tảng đám mây.

        \subsubsection{Kiến trúc phần mềm tổng thể}
            Phần mềm hệ thống được thiết kế theo kiến trúc phân lớp (Layered Architecture) và module hóa, áp dụng nhất quán cho cả hai MCU LAN và MCU WAN. Mỗi firmware được chia thành 4 lớp chính:
            \begin{itemize}
                \item Driver Layer
                \item Board Support Package (BSP)
                \item Middleware Layer
                \item Application Layer
            \end{itemize}

            Việc phân lớp rõ ràng giúp:
            \begin{itemize}
                \item Tách biệt logic ứng dụng và phụ thuộc phần cứng
                \item Dễ dàng mở rộng, thay thế module
                \item Giảm rủi ro ảnh hưởng dây chuyền khi thay đổi một thành phần
            \end{itemize}

            \subsubsection{Giải pháp phần mềm cho Master WAN-MCU}

            MCU WAN giữ vai trò Application Master, quản lý WAN, Cloud và điều phối toàn hệ thống.

            \paragraph{Application Layer – MCU WAN:}
                Các thành phần chính:
                \begin{itemize}
                    \item Main Control: điều phối hệ thống, quản lý trạng thái gateway.
                    \item Internet Communication Handler:
                    \begin{itemize}
                        \item Ethernet Handler Task
                        \item Wi-Fi Handler Task
                        \item LTE / NB-IoT Handler Task
                    \end{itemize}
                    \item Server Communication Handler:
                    \begin{itemize}
                        \item MQTT Handler Task
                        \item HTTP Handler Task (mở rộng)
                        \item CoAP Handler Task (mở rộng)
                    \end{itemize}
                    \item MCU LAN Communication Handler: quản lý kênh Quad SPI, UART và GPIO với MCU LAN.
                    \item FOTA \& Bridge Bootloader: cập nhật firmware cho cả hai MCU.
                \end{itemize}

                Dữ liệu từ MCU LAN được MCU WAN đóng gói và gửi lên Cloud theo cấu hình (MQTT/HTTP/CoAP).

            \paragraph{Middleware Layer – MCU WAN:}
                \begin{itemize}
                    \item ESP IDF MQTT
                    \item Ethernet / Wi-Fi / LTE / NB-IoT Handler
                    \item ESP OTA Handler
                    \item FreeRTOS
                \end{itemize}

                \paragraph{BSP \& Driver – MCU WAN:}
                \begin{itemize}
                    \item BSP: SIM7600, Ethernet Module, MCU LAN Communication, RTC, IO Expander.
                    \item Driver: UART, SPI, USB, I2C, MAC, GPIO, Wi-Fi Driver.
                \end{itemize}

        \subsubsection{Giải pháp phần mềm cho MCU LAN (Slave LAN-MCU)}
            MCU LAN chịu trách nhiệm chính cho Sensing Domain và LAN Network Domain, tập trung vào thu thập, tiền xử lý và lưu trữ dữ liệu.

            \paragraph{Application Layer – MCU LAN:}
                Tầng Application của MCU LAN bao gồm các khối chính:
                \begin{itemize}
                    \item Main Control: điều phối hoạt động tổng thể của MCU LAN theo lệnh từ MCU WAN.
                    \item LAN Network Handler: quản lý các mạng cảm biến nội bộ.
                    \item Các Handler Task theo giao thức:
                    \begin{itemize}
                        \item LoRa Handler Task
                        \item Zigbee Handler Task
                        \item Bluetooth Handler Task
                        \item Z-Wave Handler Task
                        \item Thread Handler Task
                        \item CAN Handler Task
                        \item Modbus / RS-485 Handler Task (nếu được cấu hình)
                    \end{itemize}
                \end{itemize}

                Mỗi Handler Task hoạt động như một FreeRTOS task độc lập, đảm bảo:
                \begin{itemize}
                    \item Thu thập dữ liệu song song từ nhiều mạng khác nhau
                    \item Tránh blocking giữa các giao thức
                    \item Dễ dàng bật/tắt theo cấu hình mà không cần sửa firmware
                \end{itemize}

                Chức năng chung của mỗi Handler Task:
                \begin{itemize}
                    \item Đọc dữ liệu thô từ phần cứng
                    \item Kiểm tra định dạng, checksum, loại bỏ khung lỗi
                    \item Gắn nhãn nguồn dữ liệu và timestamp
                    \item Chuẩn hóa dữ liệu về định dạng khung nội bộ
                    \item Đưa dữ liệu vào hàng đợi (queue) để gửi sang MCU WAN
                \end{itemize}

            \paragraph{Middleware Layer – MCU LAN:}
                Middleware đóng vai trò trừu tượng hóa giao thức và thư viện nền:
                \begin{itemize}
                    \item Zigbee / LoRa / Thread / Z-Wave / Bluetooth Handler
                    \item Data Storage Handler (lưu dữ liệu tạm thời vào SD Card)
                    \item ESP OTA Handler (hỗ trợ cập nhật firmware)
                    \item FreeRTOS Kernel
                \end{itemize}

            Lớp này giúp Application không phụ thuộc trực tiếp vào BSP hoặc Driver.

            \paragraph{BSP \& Driver – MCU LAN:}
                \begin{itemize}
                    \item BSP quản lý giao tiếp với các module vật lý: Zigbee, LoRa, Thread, RS-485, CAN, SD Card, IO Expander.
                    \item Driver Layer cung cấp driver chuẩn: UART, SPI, I2C, SDIO, GPIO, ADC, USB.
                \end{itemize}

        \subsubsection{Cơ chế cấu hình và cập nhật}
            \begin{itemize}
                \item Toàn bộ tham số gateway được lưu trong non-volatile memory.
                \item Configuration Tools trên PC giao tiếp với gateway qua USB/UART.
                \item Cho phép:
                \begin{itemize}
                    \item Đọc cấu hình hiện tại
                    \item Chỉnh sửa module, giao thức, WAN, MQTT
                    \item Ghi cấu hình mà không cần build lại firmware
                \end{itemize}
                \item Hỗ trợ FOTA an toàn:
                \begin{itemize}
                    \item Kiểm tra checksum
                    \item Cập nhật từng MCU
                    \item Không ghi đè firmware đang chạy
                \end{itemize}
            \end{itemize}

        \subsubsection{Đánh giá giải pháp phần mềm}
            Giải pháp phần mềm đáp ứng:
            \begin{itemize}
                \item Modularity: bật/tắt module qua cấu hình
                \item Configurability: cấu hình không cần sửa firmware
                \item Reliability: watchdog, queue, retry, buffer
                \item Interoperability: hỗ trợ đa giao thức LAN/WAN
                \item Scalability: dễ mở rộng thêm protocol hoặc cloud service
            \end{itemize}
