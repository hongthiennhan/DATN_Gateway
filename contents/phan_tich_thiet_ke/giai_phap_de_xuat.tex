\section{Giải pháp đề xuất}
    Giải pháp hướng tới xây dựng một IoT Gateway có tính linh hoạt cao và khả năng cấu hình tùy biến, thông qua việc tích hợp giữa kiến trúc phần cứng mô-đun và hệ thống xử lý phân tán. Cách tiếp cận này giúp tối ưu hóa chi phí sản xuất và rút ngắn thời gian triển khai cho các kịch bản ứng dụng đa dạng.
        \subsection{Giải pháp phần cứng}

            \subsubsection{Phần cứng mô-đun hóa}
            Hệ sinh thái phần cứng được thiết kế để đảm bảo khả năng tích hợp và nâng cấp mà không làm thay đổi thiết kế lõi của hệ thống:
            \begin{itemize}
                \item \textbf{Bo mạch chủ (Baseboard) chuẩn hóa:} Đóng vai trò là nền tảng trung tâm, tích hợp các khe cắm với giao tiếp vật lý và giao thức được chuẩn hóa để kết nối đồng bộ với các Module Adapter.
                \item \textbf{Module Adapter linh hoạt:} Đóng vai trò cầu nối trung gian, thực hiện nhiệm vụ chuyển đổi và chuẩn hóa các chuẩn giao tiếp từ thiết bị thương mại về một giao thức nội bộ thống nhất.
            \end{itemize}

            \subsubsection{Tối ưu hóa nhân xử lý chính}
            Thay vì sử dụng các bộ vi xử lý (CPU) hiệu năng cao vốn đòi hỏi thiết kế PCB nhiều lớp phức tạp và làm tăng giá thành linh kiện, nhóm lựa chọn dòng Vi điều khiển (MCU) làm nhân xử lý chính dựa trên các tiêu chí kỹ thuật:
            \begin{itemize}
                \item \textbf{Cân bằng Hiệu suất - Chi phí:} Đảm bảo tài nguyên phần cứng đủ mạnh và hỗ trợ đa dạng ngoại vi với giá thành thấp.
                \item \textbf{Hiệu quả năng lượng:} Đáp ứng các tiêu chuẩn khắt khe cho thiết bị vận hành liên tục hoặc sử dụng nguồn năng lượng hạn chế.
                \item \textbf{Hệ sinh thái hỗ trợ:} Tận dụng mã nguồn mở dồi dào để đẩy nhanh tốc độ phát triển và tối ưu hóa Firmware.
            \end{itemize}

            \subsubsection{Kiến trúc phân tán Dual-MCU}
            Để giải quyết giới hạn về tài nguyên bộ nhớ khi phải vận hành đồng thời nhiều ngăn xếp giao thức (protocol stacks) phức tạp, hệ thống sử dụng hai MCU chuyên biệt hóa:
            \begin{itemize}
                \item \textbf{WAN-MCU (Master):} Quản lý luồng dữ liệu mạng diện rộng, điều phối toàn bộ hoạt động hệ thống và quản trị các tác vụ cấp cao.
                \item \textbf{LAN-MCU (Slave):} Chuyên trách giao tiếp mạng nội bộ, quản lý việc thu thập dữ liệu từ các Module Adapter và thiết bị đầu cuối.
            \end{itemize}
            Hai khối xử lý này được liên kết chặt chẽ thông qua giao thức truyền thông tốc độ cao và hệ thống tín hiệu điều khiển logic, đảm bảo tính đồng bộ và duy trì độ trễ thấp trong quá trình trao đổi thông tin.


    \subsection{Giải pháp phần mềm}
        Giải pháp phần mềm được xây dựng nhằm đáp ứng các yêu cầu cốt lõi của hệ thống IoT Gateway, bao gồm: tính module hóa (Modularity), khả năng cấu hình linh hoạt (Configurability), độ ổn định -- tin cậy cao, khả năng mở rộng và dễ bảo trì.

        Phần mềm phải tận dụng hiệu quả kiến trúc \textbf{Dual-MCU Master--Slave}, phân tách rõ ràng trách nhiệm giữa hai vi điều khiển để tối ưu tài nguyên phần cứng, đồng thời bảo đảm luồng dữ liệu thông suốt từ thiết bị cảm biến tới nền tảng đám mây.

        \subsubsection{Kiến trúc phần mềm tổng thể}
            Phần mềm hệ thống được thiết kế theo kiến trúc phân lớp (Layered Architecture) và module hóa, áp dụng nhất quán cho cả hai MCU LAN và MCU WAN. Mỗi firmware được chia thành 4 lớp chính:
            \begin{itemize}
                \item Driver Layer
                \item Board Support Package (BSP)
                \item Middleware Layer
                \item Application Layer
            \end{itemize}
            Việc phân lớp rõ ràng giúp:
            \begin{itemize}
                \item Tách biệt logic ứng dụng và phụ thuộc phần cứng
                \item Dễ dàng mở rộng, thay thế module
                \item Giảm rủi ro ảnh hưởng dây chuyền khi thay đổi một thành phần
            \end{itemize}

            \subsubsection{Giải pháp phần mềm cho Master WAN-MCU}

            MCU WAN giữ vai trò Application Master, quản lý WAN, Cloud và điều phối toàn hệ thống.

            \paragraph{Application Layer - MCU WAN:}
            Các thành phần chính:
                \begin{itemize}
                    \item \textbf{Main Control:} điều phối hệ thống, quản lý trạng thái gateway.
                    
                    \item \textbf{Internet Communication Handler:}
                    \begin{itemize}
                        \item Ethernet Handler Task
                        \item Wi-Fi Handler Task
                        \item LTE Handler Task
                    \end{itemize}
                
                    \item \textbf{Server Communication Handler:}
                    \begin{itemize}
                        \item MQTT Handler Task
                        \item HTTP Handler Task
                        \item CoAP Handler Task
                    \end{itemize}
                
                    \item \textbf{MCU LAN Communication Handler:} quản lý kênh SPI, UART và GPIO với MCU LAN.
                    
                    \item \textbf{FOTA \& Bridge Bootloader:} cập nhật firmware cho cả hai MCU.
                    
                    \item \textbf{Web Config Handler:} cung cấp cổng cấu hình qua trình duyệt, bao gồm các API đọc cấu hình, ghi cấu hình, đọc trạng thái hệ thống và yêu cầu khởi động lại thiết bị.
                \end{itemize}

            \paragraph{Middleware Layer – MCU WAN:}
                \begin{itemize}
                    \item ESP IDF MQTT/HTTP/CoAP
                    \item Ethernet/Wi-Fi/LTE Handler
                    \item ESP OTA Handler
                    \item FreeRTOS
                \end{itemize}

                \paragraph{BSP \& Driver – MCU WAN:}
                \begin{itemize}
                    \item \textbf{BSP:} SIM7600, Ethernet Module, MCU LAN Communication, RTC, Stack Handler.
                    \item \textbf{Driver:} UART, SPI, USB, I2C, MAC, GPIO, Wi-Fi Driver.
                \end{itemize}

        \subsubsection{Giải pháp phần mềm cho MCU LAN (Slave LAN-MCU)}
            MCU LAN chịu trách nhiệm chính cho Sensing Domain và LAN Network Domain, tập trung vào thu thập, tiền xử lý và lưu trữ dữ liệu.

            \paragraph{Application Layer – MCU LAN:}
                Tầng Application của MCU LAN bao gồm các khối chính:
                \begin{itemize}
                    \item \textbf{Main Control:} điều phối hoạt động tổng thể của MCU LAN theo lệnh từ MCU WAN.
                    \item \textbf{FOTA:} cập nhật firmware cho MCU.
                    \item \textbf{Module Monitor Task:} theo dõi trạng thái stack, phát hiện module, khôi phục cấu hình từ NVS và khởi động lại handler task khi cấu hình thay đổi trong lúc runtime.
                    \item \textbf{Các Handler Task theo giao thức:}
                    \begin{itemize}
                        \item LoRa Handler Task
                        \item Zigbee Handler Task
                        \item Bluetooth Handler Task
                        \item RS-485 Handler Task
                    \end{itemize}
                \end{itemize}
                
                Mỗi Handler Task hoạt động như một FreeRTOS task độc lập, đảm bảo:
                \begin{itemize}
                    \item Thu thập dữ liệu song song từ nhiều mạng khác nhau.
                    \item Tránh blocking giữa các giao thức.
                    \item Dễ dàng bật/tắt theo cấu hình mà không cần sửa firmware.
                \end{itemize}
                
                Chức năng chung của mỗi Handler Task:
                \begin{itemize}
                    \item Đọc dữ liệu thô từ module.
                    \item Kiểm tra định dạng, checksum, loại bỏ khung lỗi.
                    \item Gắn nhãn nguồn dữ liệu và timestamp.
                    \item Chuẩn hóa dữ liệu về định dạng khung nội bộ.
                    \item Đưa dữ liệu vào hàng đợi (queue) để gửi sang MCU WAN.
                \end{itemize}

            \paragraph{Middleware Layer – MCU LAN:}
                Middleware đóng vai trò trừu tượng hóa giao thức và thư viện nền:
                \begin{itemize}
                    \item Zigbee/LoRa/Bluetooth Handler
                    \item Data Storage Handler (lưu dữ liệu tạm thời vào SD Card)
                    \item ESP OTA Handler (hỗ trợ cập nhật firmware)
                    \item FreeRTOS Kernel
                \end{itemize}

            Lớp này giúp Application không phụ thuộc trực tiếp vào BSP hoặc Driver.

            \paragraph{BSP \& Driver – MCU LAN:}
                \begin{itemize}
                    \item BSP quản lý giao tiếp với các module vật lý: RS-485, SD Card, IO Expander.
                    \item Driver Layer cung cấp driver chuẩn: UART, SPI, I2C, SDIO, GPIO, ADC, USB.
                \end{itemize}

        \subsubsection{Cơ chế cấu hình và cập nhật}
            \begin{itemize}
                \item Toàn bộ tham số gateway được lưu trong non-volatile memory.
                \item Configuration Tools trên PC giao tiếp với gateway qua USB/UART.
                \item Web Config Portal được gateway host lên để người dùng có thể truy cập và cấu hình.
                \item Cho phép:
                \begin{itemize}
                    \item Đọc cấu hình hiện tại.
                    \item Chỉnh sửa module, giao thức, WAN, MQTT.
                    \item Ghi cấu hình mà không cần build lại firmware.
                \end{itemize}
                \item Hỗ trợ FOTA an toàn:
                \begin{itemize}
                    \item Kiểm tra checksum.
                    \item Cập nhật từng MCU.
                    \item Không ghi đè firmware đang chạy.
                \end{itemize}
            \end{itemize}

        \subsubsection{Đánh giá giải pháp phần mềm}
            Giải pháp phần mềm đáp ứng:
            \begin{itemize}
                \item Modularity: bật/tắt module qua cấu hình
                \item Configurability: cấu hình không cần sửa firmware
                \item Reliability: watchdog, queue, retry, buffer
                \item Interoperability: hỗ trợ đa giao thức LAN/WAN
                \item Scalability: dễ mở rộng thêm protocol hoặc cloud service
            \end{itemize}
